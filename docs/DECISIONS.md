# Framework decisions

Decisions about the framework itself. Each site keeps its own `DECISIONS.md` for its kickoff answers.

| Date | Decision | Why |
|---|---|---|
| 2026-10-22 | The framework lives in its own repo, `framework-b`. Each site gets a new, separate repo. No site's history or content is shared | Keep every site and the framework independent |
| 2026-10-22 | Page layer: Astro 7, mostly static output, structured so EmDash can be switched on without restructuring | Reusable components for agents; fast static pages |
| 2026-10-22 | Forms: the framework's own multi-step form engine, driven by a JSON schema. SurveyJS stays an option for complex branching | About 5 KB compressed vs about 450 KB for SurveyJS core + UI; already passed axe and Lighthouse |
| 2026-10-22 | Every form is an auto opt-in: one line under the submit button says the visitor will get emails and can unsubscribe at any time | Owner's choice. Allowed under US CAN-SPAM. Sites targeting the EU or Canada are flagged, because GDPR and CASL generally require consent |
| 2026-10-22 | Two modes: idea (`workers.dev`) and launch (own domain), with a `promote` script between them | Most launches are cheap demand tests that may never get a domain |
| 2026-10-22 | Idea-mode email goes through a Google Apps Script mailer in the owner's Gmail: a notification to the owner and an optional auto-reply to the lead | Cloudflare can only send from domains set up for Email Routing, and `workers.dev` isn't one. Apps Script is free (100 recipients a day on a personal Gmail) and needs no domain |
| 2026-10-22 | Launch-mode email: Cloudflare `send_email` for owner notifications; Resend Free on `mail.<domain>` for lead confirmations; newsletters from `updates.<domain>` (newsletter sender and notifications refined on 2026-10-27, below) | Separates the domain's web reputation from its email reputation |
| 2026-10-22 | Lead confirmations are plain transactional mail: text plus minimal HTML, one link, no tracking, no `List-Unsubscribe` headers | Bulk-mail headers and styled HTML sent the test build's confirmations to Gmail Promotions |
| 2026-10-22 | R2 uploads are on by default: a "Do you need to send us something?" file field on the contact form | Keeps the upload path tested on every site |
| 2026-10-22 | Search indexing is a per-site choice in both modes; ideas default to `noindex` | Some ideas should be found from day one |
| 2026-10-22 | Client editing (EmDash) is a per-site switch in both modes. Each EmDash site needs its own D1 and R2 | An assistant or co-worker may need to edit content |
| 2026-10-22 | Ideas share one D1 and one uploads bucket; one account-wide backup Worker covers every site | The Free plan allows 10 D1 databases and 5 Cron Triggers per account |
| 2026-10-22 | Nothing a live site needs runs on the owner's machine. CI is Workers Builds; schedules are Cloudflare Cron; state is in GitHub | Owner's standing rule |
| 2026-10-22 | Design direction is asked through a design intake, not silently inferred (autopilot is an explicit exception, below) | Undirected AI builds converge on the same look |
| 2026-10-22 | Sites carry a vendored copy of `packages/core` stamped with a version. Updating means an agent copies a newer tagged version in on a branch, the preview and QA gate run, and the owner merges | A copied template never receives later fixes. Vendoring avoids build-time credentials for the private repo, and nothing reaches a live site without a passing preview |
| 2026-10-22 | Decided by the owner: the Cloudflare change token lives once as a GitHub Actions secret; every Cloudflare-changing step is a workflow agents trigger; agents hold only a read-only token for diagnostics. Amended the same day: the secrets and the callers live in a private ops repo, because `framework-b` became public | One place to rotate; agents never see the change token. Verified 2026-10-22 that a cloud agent session can trigger workflows by push and by `workflow_dispatch`. GitHub Free gives private repos 2,000 Actions minutes a month, and organization secrets don't reach private repos on Free ([GitHub docs](https://docs.github.com/en/actions/security-for-github-actions/security-guides/using-secrets-in-github-actions), checked 2026-10-22) |
| 2026-10-22 | Paid design-reference libraries (Refero, Mobbin) are optional inputs, never required | Owner's choice |
| 2026-10-22 | Autopilot design is allowed: when the owner says "autopilot" or doesn't answer, the agent infers answers, builds three tiles, ranks them by pairwise vision comparison, and marks every choice `inferred`. "Redo the design" re-runs the intake later | Owner's choice; recommended mainly for idea sites |
| 2026-10-22 | Pushes to `main` go live immediately through Workers Builds, so `main` takes changes only through pull requests. Enforcement: free pre-push hook (PR #1) unless the owner chooses GitHub Pro, which enforces branch protection on private repos ([GitHub docs](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/defining-the-mergeability-of-pull-requests/about-protected-branches), checked 2026-10-22) | On the first live build an agent made 10 commits straight to `main`, each deployed without a preview |
| 2026-10-22 | The design phase is approved as proposed (nine-step intake). Free tools from the second research round supplement it without new questions; Apify and paid libraries stay optional | Owner's review. Gallery and review scraping are rejected on terms; fonts are OFL-only until Fontshare's licence is read |
| 2026-10-22 | Uploads go through the Worker: the submit response returns a signed single-use URL, and the file is streamed to R2. No presigned R2 URLs | No R2 S3 key pair per site and no bucket CORS. Streaming stays inside the Free plan's 10 ms CPU limit ([Workers limits](https://developers.cloudflare.com/workers/platform/limits/), checked 2026-10-22) |
| 2026-10-22 | Indexing headers for static pages come from a generated `_headers` file, not Worker code | Static assets are served without running the Worker; `_headers` supports host patterns such as `https://:worker.:subdomain.workers.dev/*` ([static assets headers](https://developers.cloudflare.com/workers/static-assets/headers/), checked 2026-10-22) |
| 2026-10-22 | One `SIGNING_SECRET` per site signs unsubscribe links and upload URLs, with a distinct prefix for each use | One fewer secret to set and rotate |
| 2026-10-22 | Filling in any form re-subscribes a visitor who unsubscribed earlier | Owner's rule: every form is a sign-up form, so a new submission is a new opt-in. Each lead row records the wording shown |
| 2026-10-22 | The Apps Script mailer runs in the owner's existing Gmail for now; the owner filters it in his mail client and may move it to a dedicated account later | Owner's choice. Moving later means redeploying the script and updating `MAILER_URL` and `MAILER_SECRET` |
| 2026-10-22 | Backups use D1's export API from a scheduled Workflow, covering every database in the account, streamed to R2 with 90-day expiry | No per-site bindings or registry to keep in sync; each step retries on its own and stays inside the Free plan's 10 ms CPU per step. Pattern from Cloudflare's own example ([backup D1](https://developers.cloudflare.com/workflows/examples/backup-d1/), checked 2026-10-22) |
| 2026-10-22 | `framework-b` is public (owner's choice), so it holds no list of real sites, no site names and no account identifiers. Backups and other ops discover resources from the Cloudflare API instead | Public repos get free branch rulesets and unlimited Actions minutes |
| 2026-10-22 | Site repos are created by a workflow in the private ops repo with a fine-grained GitHub token (`GH_SITES_TOKEN`), not by hand | Owner's choice: one prompt per site |
| 2026-10-22 | Self-test sites (`selftest-*`) are torn down without asking each time, including their GitHub repo. Their rows are still exported to `framework-backups` first. Real sites need the owner to type `delete <id>` | Owner's approval. Self-tests run often and hold only test data |
| 2026-10-22 | The Cloudflare Workers and Pages GitHub app has access to all of the owner's repositories | Needed so Workers Builds can connect each new `site-<id>` repo without a manual step. Owner changed it |
| 2026-10-22 | The backup Workflow is started by a Worker Cron Trigger, not by Workflow `schedules` | Deploying with `schedules` failed: "scheduled Workflows require a paid Workers plan". Cron Triggers are on the Free plan (5 per account; this uses 1) |
| 2026-10-23 | Client editing signs editors in through Cloudflare Access (`<id> editor` on `/_emdash/*`), not EmDash passkeys or email links | Same login as `/admin`; email sign-in would need Cloudflare Email Sending to arbitrary recipients, which needs Workers Paid. EmDash supports Access as its auth mode |
| 2026-10-23 | EmDash content uses its own D1 database, media bucket and session KV per site, bound as `CMS_DB`, `MEDIA` and `SESSION`; leads stay in `DB`/`UPLOADS` | EmDash tables can't be shared between sites; core and leads stay unchanged |
| 2026-10-23 | EmDash's maintenance Cron Trigger runs hourly, not every minute | It only needs to run that often for scheduled publishing; one trigger per site whatever the frequency, so the account limit (5) is the real constraint |
| 2026-10-23 | `editing on` is a switch script that rewrites the site from `starter/editing/`, not a runtime flag | Static sites keep no EmDash packages and stay fully static; an editing site is an ordinary EmDash-on-Astro project an agent can read |
| 2026-10-23 | An idea site may be indexed when the owner asks (`indexing: on`). Its workers.dev address becomes canonical and indexable; previews and other hosts stay noindex | Owner's choice for the first real site |
| 2026-10-23 | A newsletter asked for on an idea site starts as subscriber collection only: every form already opts people in, with one-click unsubscribe. Sending starts at launch, from the site's own domain | Bulk email from a free address hurts deliverability and needs a postal address (CAN-SPAM); the newsletter module is launch-only (SPEC section 10) |
| 2026-10-23 | `DESIGN.md` (Google format, linted by `@google/design.md` 0.4.0) is the only source of the look; `tokens.css` is generated, Tailwind's default palette is switched off, and a fixed token contract lets one section library serve every design | Sections can't drift into raw colours, and any design that meets the contract (including contrast) works with every section |
| 2026-10-23 | One section schema serves static sites and EmDash: the same definitions check `src/content/*.json`, render the components and become EmDash block types | An editing site and a static site share components and content shape; switching editing on moves the page content in unchanged |
| 2026-10-23 | Forms outline inputs with a `field` colour that must reach 3:1 against the background; `line` stays decorative | WCAG 2.2 1.4.11 (non-text contrast). The starter used `line` for input borders at about 1.3:1 |
| 2026-10-23 | Autopilot design for the first real site: the owner asked for "trustworthy and friendly" and delegated the rest; the agent chose the direction from research and recorded every inferred business promise in the site's `PRODUCT.md` for the owner to confirm | Owner's instruction |
| 2026-10-23 | Sites are updated by `scripts/site/update.mjs`: a three-way merge of every framework-owned file (starter and core) from the commit in the site's `framework.lock.json` to the new ref, on a branch, tested, then a pull request in the site repo. Conflicts are left for a person as `<file>.framework-new` | Extends the vendored-core decision to the starter files: fixes to scripts, sections and layouts reach existing sites without overwriting site edits, and nothing reaches production without the owner's merge |
| 2026-10-26 | Preview checks get through Access with a service token minted per run (30 minutes, deleted at the end), admitted by one reusable Service Auth policy that accepts any valid service token on each previews application | No long-lived secret to store or rotate; the session can't write ops secrets anyway. Only account administrators can create service tokens, so the policy admits nothing else |
| 2026-10-26 | QA sends Access headers only to the checked origin, including inside Lighthouse | Third-party scripts on the page (Turnstile) must never see the token; Access's strict mode needs the headers on every request |
| 2026-10-26 | Kickoff answers live in the site's `brief.json`, each marked stated, inferred or default, and `create` accepts the brief | One prompt becomes one checked file; DECISIONS rows come from it instead of being hand-written |
| 2026-10-26 | Impeccable's detector is part of the QA gate (source, and each page at 1280 and 390 px through `--cdp`); its DESIGN.md colour, radius and font-size advisories fail the gate; no Stylelint | One tool checks both the AI-design tells and the design contract on the rendered page, including previews behind Access. Stylelint would only see CSS, while the starter styles mostly with Tailwind utilities |
| 2026-10-26 | Style tiles are real builds of the site per draft, not mock-ups; the autopilot judge is the agent's own vision model answering prepared ballots, not an API call | Tiles show exactly the fonts, tokens and components the site would ship. The judge was calibrated as the session model (trials.md); calling another model would need a key and a new calibration |
| 2026-10-26 | Image credits live in `design/credits.json`, seeded into existing sites once by `site update` | `src/content/` holds pages; a ledger the framework ships must not be overwritten once the site edits it |
| 2026-10-27 | Full sites are content files: every `src/content/<slug>.json` is a page, rendered by one route from the section library | One way to build any page; the same content checks, components and QA cover every page |
| 2026-10-27 | Images live in `src/assets/images/` and go through Astro's `<Image>`; open-licensed photos come from Openverse via `scripts/images.mjs` with credits written automatically and a `/credits` page | Optimized responsive images with no service to pay for; licence terms met by construction; the agent looks at a contact sheet before choosing |
| 2026-10-27 | CRM mirror without a Cloudflare Queue: the Worker copies each lead in `waitUntil` to a Google Sheet (through the Apps Script mailer) and/or a signed webhook, keyed by the lead id; the ops `site crm sync` resends safely | The token Workers Builds creates has no Queues permission, so it could not register a queue consumer on deploy; D1 already keeps every lead and both targets dedupe by id |
| 2026-10-27 | Drips run as one Cloudflare Workflow instance per lead, configured in `site.config.json`, sent through Resend from the site's `mail.<domain>` | No Cron Trigger (the Free plan allows 5 per account) and no Queue (the Builds token can't register a consumer); a Workflow deploys with Workers Scripts Write, and sleeping instances don't count toward the 100 running ones. Emails live in the config so the Worker has them without a build step |
| 2026-10-27 | `editing off` exports with EmDash's own `export-seed` from a SQLite copy of the content database, and keeps the static files in `editing/static/` | `export-seed` is EmDash's documented export, so a schema change inside EmDash doesn't break it. The site repo has no other copy of its static files once `on` has replaced them. Nothing in Cloudflare is deleted, because the content database holds the editors' history |
| 2026-10-27 | Taking a site off its domain is "park" (detach, hold, pause, move; a record to undo it), not deletion, and always follows a full snapshot | Worker secret values can't be read back, so a deleted Worker can't be restored exactly; parking frees the domain and keeps everything else as it was |
| 2026-10-27 | Newsletters and drips send from `mail.<domain>`, the same Resend domain as auto-replies, not `updates.<domain>` | Resend Free verifies 3 domains per account; a second domain per site would halve the number of launch sites ([quotas](https://resend.com/docs/knowledge-base/account-quotas-and-limits), checked 2026-10-27) |
| 2026-10-27 | A launch site's owner notifications use Cloudflare `send_email` only when the site owns the whole zone and its apex receives no mail elsewhere; otherwise they keep going through the Apps Script mailer | Email Routing takes over the zone's MX records, which would break a mail provider the owner already uses on that domain |
| 2026-10-27 | Cron days are written as names (`MON`), not numbers | Cloudflare numbers weekdays from 1 = Sunday; the backup Worker's `* * 1` ran on Sundays while every doc said Mondays ([Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/), checked 2026-10-27) |
| 2026-10-27 | A docs check runs in CI (`scripts/docs-check.mjs`): every path, script and ops workflow the docs name must exist, and every ops caller must match its reusable workflow | The v1 docs audit found docs pointing at removed folders and an outdated ops template; a check keeps that from coming back |
| 2026-10-28 | Core 0.5.0 adds a checkbox consent mode (`optIn.mode`), `/go` and acceptance of an older unsubscribe-link secret (`LEGACY_UNSUB_SECRET`, or the binding `legacyUnsubSecret` names, because an adopted Worker's existing secret can't be read back or renamed) | Needed to bring an existing site onto Framework B without breaking its consent rules, printed QR codes or links already in inboxes. The checkbox mode is also the consent model GDPR and CASL generally require, so the brief now uses it for EU, UK and Canadian audiences |
| 2026-10-28 | Owner's design decisions: generated imagery is allowed and its style becomes a kickoff question; fonts may come from any open source that licenses web and logo use (OFL by default); motion is CSS first, with the lightest library that fits; free options first, cheap paid options considered later | Owner's review of the design research report. Guard rail from research: generated images never show the business's own people, premises, products or results, and are labelled as generated |
| 2026-10-28 | The design upgrade is proven by moving the first real site fully onto Framework B, with its existing leads copied (originals untouched) | Owner's choice: the site predates most of the framework and shows every design weakness the research found |
| 2026-10-28 | The skeleton becomes part of the design: `composition` and `imagery` blocks in DESIGN.md, a `variant` and a `phone` setting on every section, a phone action bar, and a QA phone budget (default 6 screens for the home page) | Every site had the same layout with a different skin, and phone pages ran 8–9 screens. Putting the choices in DESIGN.md lets the drafts, tiles and judge compare whole layouts, and putting them on sections lets EmDash editors change them |
| 2026-10-28 | Motion ships as CSS only (scroll-driven reveal inside `@supports`, view transitions, hover and press states), all under `prefers-reduced-motion: no-preference` | Scroll-driven animations are in every current engine (Firefox from 2026-10-27) and cost no JavaScript; older browsers simply show the content. A site that needs scripted motion adds the smallest library that does it |
| 2026-10-28 | Generated images use Workers AI's FLUX.2 [klein] 4B, run from the agent's environment with a token that can only run models (a network secret on a Claude cloud environment, or `WORKERS_AI_TOKEN`) | Apache 2.0, free within 10,000 neurons a day (about 60 images), and the same account as the sites. FLUX.1 [schnell] ignores width and height; the larger FLUX.2 models are licensed non-commercially. Untested live until the owner creates the token |
| 2026-10-28 | Photorealistic generated images carry a visible "Generated image" label and show no faces; every generated image is listed on `/credits` | Nearly 90% of people want to know whether an image was made with AI, and AI pictures of people or products read as misleading (Getty Images VisualGPS, checked 2026-10-28). Illustrations are plainly not photos, so the credits page is enough for them |
| 2026-10-28 | Logos are drawn by the brand kit from the design's own display font, converted to outlines, with an optional Phosphor mark; no logo generator or AI image model | Text in AI images is unreliable and a logo must be exact, editable and free of other brands' marks. Outlines don't depend on a web font loading |
| 2026-10-28 | Core 0.6.0 and the starter gain what an adopted site's existing pages need: radio and checkbox-group fields with step headings, inline bold, italic and links in every text field, list and people sections, footer columns and a legal line, and noindex content pages | The first adoption must keep its content as it is; without these, its forms, rules lists, team section and footer could only be rebuilt by changing their wording or structure. Each is general enough for any site |
| 2026-10-28 | Text columns use the design's `prose` width (`max-w-(--container-prose)`), not Tailwind's `max-w-prose` | Tailwind 4's `max-w-prose` is a fixed 65ch and ignores the theme, so DESIGN.md's prose width never applied; on a narrow font 65ch ran to 86 characters a line and failed the line-length check. Found building the first adopted site |
| 2026-10-28 | Launch and adopted sites get their own production database only; their previews use the shared `fb-previews`, where core scopes every query by `site` | The Free plan allows 10 D1 databases per account (https://developers.cloudflare.com/d1/platform/limits/, checked 2026-10-28); a staging database per site used half of them for test rows. Sites launched earlier keep their `<id>-staging`. Chosen by the owner |
| 2026-10-28 | No "Generated image" label on any image (replaces the row above that added one); generated images stay listed on `/credits`, and the rules on what they may show stay | Owner's decision. The EU AI Act's disclosure duty covers deep fakes (content resembling real people, objects, places or events that would falsely appear authentic), and for evidently artistic work only a disclosure that doesn't hamper it: https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-50, checked 2026-10-28 |
| 2026-11-02 | The image credits page is titled "Website assets" (footer link and heading); its URL stays `/credits` so links already in use keep working. Credits never sit beside an image; they appear only on that page | Owner's decision for the first adopted site. The footer and heading were the only places the old label appeared; the rule that credits stay off the page beside images already held in the starter | 
| 2026-11-03 | Framework B keeps the method for finding a site's design (routes: whole page skeletons on real content, the owner's pick and conditions, build on the site, measure the built pages), the rules and the checks; not any one site's look. A layout a site needs is built in that site and moves into the starter only when a second site needs it. The QA gate measures text over pictures against the picture, and content stays out of sideways strips on phones | Owner's decision: the test site is the working example, the framework is the concepts, rules and methodology. Building the test site's chosen route found text at 1.2:1 over photos that every existing check passed (SPEC section 12, "Design routes") |
| 2026-11-03 | Sideways strips on phones stay an option, also for content such as a wall of services, and `PHONE_AUTO` is unchanged. Every strip gets the swipe cue: an accent bar as long as the share on screen, with an arrow head pointing the way there is more; the QA gate lists each strip | Owner's decision and design. The browser's scrollbar can't be the cue on phones, where it is an overlay drawn only while scrolling (SPEC section 12, "Swipe cue") |
| 2026-11-03 | Phones: the QA gate fails a link or button the action bar cuts in half on the first screen and text left under the bar at the end of the page; a hero action the bar already shows is left out of the hero on phones; accordion rows get a plus in an accent-outlined square (a minus when open) | Owner's items 2 and 3. On the first adopted site the hero's second link sat half under the bar, which already carried it; the old accordion cue was a small `+` |
| 2026-11-03 | In a set of cards where some carry photos, most do; a type-only card is a deliberate accent, and each photo is chosen for what its card says. The Website assets lists keep to the prose width | Owner's decision after the test site showed three of six service posters without photos because only three had been sourced. Longer credit lines (with photographers' names) ran to about 133 characters at 1280 px and failed Impeccable's line-length rule |
| 2026-11-03 | Library of Congress photographs are an image source with a script (search, rights check, master scan, border crop, credit); photos taken off a page go to the site's image library (design/library in the site), never the bin; each credit can say where the photo goes and why; a design runs through every page (the QA report lists content pages without pictures), and a card set with photos has them on more than half its cards (QA fails otherwise) | Owner's decisions on the first adopted site: old public-domain photographs, no generated images there, keep every photo for later pages, roll the design through the whole site. The hand process this replaces lived only in a session's scratch files |
| 2026-11-03 | An image field can carry a focal point (`focalX`, `focalY`: EmDash's media fields, shares from 0 to 1), and every layout crops toward it | On the test site the subject of an archive photo (a sign at the top of a portrait scan) was lost on either the wide hero band or the phone crop, whichever way the file was cut; cropping the file can't serve two shapes (SPEC section 12, "Focal points") |
| 2026-11-04 | One design language on every page. A route is a page family: it fixes the title treatment (`composition.titleCase`) and the hero layouts for the home page and for every other page (`composition.heroes`), which the content check enforces, and the home page may only be louder. A photo goes with the title or with text beside it, never in a bare band; the statement hero takes no picture. The QA gate fails a page title that differs from the home page's and a bare photo banner, and draws the site sheets | Owner's decision: the test site's inner pages "kinda feel separate from the home", and "a large plain image taking up full width space on the screen is not a modern design"; the consistency "needs to be a part of framework b overall" and has to persist through the project. Measured on that site: the home title 112 px, uppercase, left, on the photo; every inner title 84 px, as written, centred, over a bare 1216×521 band (SPEC section 12, "One design language") |
| 2026-11-04 | Variety within one family: the route names a family of inner-page hero layouts and each page picks one; flow covers the whole page: every content page ends on the route's closing section (`composition.closing`) and no page runs more than half a screen longer without a picture than the home page | Owner's decision: "a variety WITH consistent look, feel, and flow", "not just the hero ... entire page length and flow". On the test site an inner page ran 4.4 screens without a picture against the home page's 3.6, and no inner page ended the way the home page does |
| 2026-11-04 | Every site gets a style guide once the home page carries the route, before the other pages: `STYLE-GUIDE.md` (ten sections, written for the owner, a designer or a printer) rendered with the site's real tokens, components and pages into `design/style-guide/style-guide.pdf`, with cited social and print sizes; the QA gate fails a guide older than DESIGN.md or STYLE-GUIDE.md | Owner's decision: a style guide "to work from once the 'general' homepage layout ... is determined" to "help decide all other pages, print, social" (SPEC section 12, "Style guide") |
| 2026-11-04 | Logos are designed, not only set: a written brief (the field's sea of sameness, clichés to avoid, ideas only this business has), five to eight concepts the agent draws as SVG in two colour roles with holes for cut-outs, a test sheet of each at its real sizes and in one colour, the owner's pick, and a full kit (dark, light, black and white versions, favicons including a 96 px PNG, a maskable icon, print PDFs, avatar, clear space and smallest sizes in the style guide). The brand kit's six layouts stay as template concepts. Supersedes the 2026-10-28 brand kit row for how a logo is made; the rule there (outlines, no AI image model) still holds | The first adopted site's owner found its brand-kit logo "super-generic" and asked for a logo method. Its field used condensed uppercase wordmarks (three of four sites looked at, 2026-11-04), and so did its logo. Sources and checks in SPEC section 12, "Logo" |
| 2026-11-04 | Logo print PDFs are made with PDFKit and SVG-to-PDFKit (MIT), fetched into the cache, not with Chromium's print to PDF | Chromium turned the logo's masks (its cut-out letters) into pictures inside the PDF; SVG-to-PDFKit keeps them as vector soft masks, and the CI test checks the PDFs hold no picture |
| 2026-11-04 | Four lenses for every design decision: the business and its goals, its field, current design (dated trend reports from the last 12 months, outside the field too) and the site's own look, recorded in `design/research.md` (seeded, site-owned; the content check fails a missing lens). The logo brief gains the business, the site's own look and current design; every designed concept names `data-from`, `data-trend` and `data-look`. Seals can set words round a circle | The owner: design research must "not only just consider industry" but the business's goals, "up-to-date current modern trends" and the site's own theme and images, consistently across Framework B. The first round of logo concepts for the first adopted site was drawn mostly from its field |
| 2026-11-05 | The site scripts' Cloudflare client retries GET requests on 429, 5xx and network failures (up to 4 attempts, exponential backoff with jitter); writes are never retried | A preview check failed on one "12001 Internal server error" while polling Workers Builds. Cloudflare advises retrying 429 and 5xx API responses with exponential backoff and random jitter ([Tunnels for platforms](https://developers.cloudflare.com/tunnel/features/tunnels-for-platforms/), checked 2026-11-05). A write may already have landed, so it fails rather than repeats |
| 2026-11-05 | Balanced sections, chosen crops and a logo as tall as the buttons.
