# Free local tools outrun design marketplaces

**For Framework B's design phase, the most useful new inputs are free, licence-clean tools and public data that run in the cloud container, not marketplace products.** The strongest is an MIT command-line tool (dembrandt) that turns any live URL into W3C DTCG tokens, a Tailwind v4 `@theme` block and a draft DESIGN.md. Next come Google Fonts' popularity rank, the Fontsource catalog and the 2025 Web Almanac, which put hard numbers on what "generic" means, and the free CrUX API, which reports real-user speed for reference sites. Hugging Face contributes one asset of real decision value: a CC-BY-4.0 set of **36,000 human pairwise judgments of AI-built landing pages**, which can calibrate the bounded pairwise critique before anyone trusts it. Apify is cheap (**$5 of free usage a month, no card**) and meets the cloud-only rule. Its design-specific Actors, though, are weeks to months old, from single developers and unrated, and its official Actors mostly duplicate the Playwright, axe and Lighthouse runs Framework B already does for free. Apify has two real niches: browserless screenshots for agents that have no browser, and finding local competitors. Hugging Face models (UIClip, Microsoft's new AesCode) earn offline trials, not dependencies. None runs inside a Worker, public Spaces sleep or break, and free accounts get no Inference Provider credits. Two uses should be rejected outright on terms. The first is scraping design galleries: Dribbble, Behance and Land-book ban scrapers, and Awwwards bars commercial use. The second is scraping Google reviews for display: the Maps terms bar copying and bulk download, and the Places API requires attribution and forbids caching. Nothing here has been adopted. Every "adopt" below is a proposal that would enter `docs/` marked untested until the template self-test covers it. Each trial has a concrete test in the closing tables. This is not legal advice.

## Free tiers cover the whole phase; durability, not price, is the constraint

**Apify's Free plan gives $5 of prepaid usage a month at $0.20 per compute unit, with no credit card. Runs are blocked when the credit runs out, and unused credit does not roll over** ([Apify pricing](https://apify.com/pricing)). A compute unit is one hour of an Actor at 1 GB of memory ([Apify docs](https://docs.apify.com/actors/running/usage-and-resources#what-is-a-compute-unit)). Agents reach Apify two ways: the hosted MCP server at `mcp.apify.com` (OAuth or a Bearer token), or plain REST. The MCP `call-actor` tool accepts `maxTotalChargeUsd`, a hard spending cap per call, which an unattended agent should always set. Apify recommends pinning tools with `?tools=` in production. Telemetry is on by default and can be turned off with `?telemetry-enabled=false` ([Apify MCP docs](https://docs.apify.com/mcp)). For short jobs, the run-sync endpoint returns dataset items in one HTTP call if the run finishes within 300 seconds ([Apify API](https://docs.apify.com/api/v2/actor-run-sync-get-dataset-items-post)). A Worker or GitHub Action can call it with `APIFY_TOKEN` held as a secret, so nothing touches the owner's computer. Apify storage expires: on Free, only "your 10 most recent runs are retained for 4 months," and unnamed storages are deleted automatically ([Apify storage docs](https://docs.apify.com/storage)). Any output worth keeping has to be copied to R2 at once.

At listed Free-tier prices, a design phase run entirely on Apify costs roughly **$0.30–0.50 per site**: eight competitor places, fifteen screenshots, five token extractions, one brand kit and five PageSpeed audits. Most of that is the $0.04-per-site token extractor. Swapping in the free in-container tools recommended below leaves only competitor discovery and screenshots, about $0.05 per site. On that arithmetic (unmeasured), the Free credit covers on the order of a hundred sites a month. Price is not the binding constraint. Supply is. The Store lists Actors "published by Apify and by independent developers" ([Apify Store](https://apify.com/store)). Almost every design-niche Actor found has fewer than 100 users and no ratings, and two were created within the last ten days. Many low-traffic Actors show about 30 runs in 30 days at close to 100% success. That pattern looks like Apify's automated daily tests rather than real use (an inference), so success rates say little about reliability.

**Hugging Face's free compute is too small to gate builds.** A free account gets 5 ZeroGPU minutes a day (2 unauthenticated, 40 on PRO). The quota resets 24 hours after first use, PRO users can buy overage at "$1 per 10 minutes," and ZeroGPU runs only Gradio Spaces ([HF ZeroGPU docs](https://huggingface.co/docs/hub/spaces-zerogpu)). Inference Providers give free users no credits at all and PRO users $2 a month ([HF Inference Providers pricing](https://huggingface.co/docs/inference-providers/pricing)). Any Gradio Space can be called headless with a two-step POST and GET ([Gradio guide](https://www.gradio.app/guides/querying-gradio-apps-with-curl)). But on 2026-10-22 the obvious design Spaces were broken: the UIClip demo, the LAION aesthetic predictor, the aesthetic-predictor-v2.5 Space, a font identifier and the SD palette generator were all in RUNTIME_ERROR ([Space API example](https://huggingface.co/api/spaces/google/mood-palette?expand[]=runtime)). Public Spaces suit one-off experiments only.

**Cloudflare cannot host the Hugging Face vision models either.** The Workers AI catalog lists 73 models but no CLIP or SigLIP image embedder, no object detector and no aesthetic scorer. It does offer FLUX image generation, vision LLMs and text embedders ([Workers AI catalog](https://developers.cloudflare.com/workers-ai/models/index.md)), with 10,000 free Neurons a day and $0.011 per 1,000 beyond that on Workers Paid ([Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/index.md)). Workers have 128 MB of memory ([limits](https://developers.cloudflare.com/workers/platform/limits/index.md)) and accept only pre-compiled WebAssembly ([Wasm docs](https://developers.cloudflare.com/workers/runtime-apis/webassembly/index.md)). Transformers.js 4.3.1, by contrast, loads precompiled WASM binaries from a CDN by default ([Transformers.js README](https://cdn.jsdelivr.net/npm/@huggingface/transformers@4.3.1/README.md)). Running it in a Worker is therefore **untested and probably blocked**. The practical rule: any Hugging Face model in Framework B runs in the CI container (GitHub Actions or Workers Builds) or not at all. Cloudflare Containers would be the fallback, and it is a paid resource that needs owner approval.

## References: owners paste live URLs, and gallery scraping is off the table

**All four major design galleries prohibit or restrict what a scraping Actor would do, even though Apify sells scrapers for three of them.** Dribbble's terms prohibit copying any part of the site "by any automated or non-automated 'scraping'" and using robots or spiders beyond human request rates. Its users keep copyright in their shots ([Dribbble Terms](https://dribbble.com/terms)). Adobe's General Terms, which cover Behance as an Adobe product (applicability inferred), ban "data mining or similar data gathering and extraction methods… including data scraping for machine learning" ([Adobe General Terms](https://www.adobe.com/legal/terms.html)). Behance's robots.txt also blocks ClaudeBot, GPTBot and other AI crawlers ([Behance robots.txt](https://www.behance.net/robots.txt)). Awwwards says its content "may not be used for commercial purposes unless expressly authorized" ([Awwwards Terms](https://www.awwwards.com/terms)). Land-book's January 2026 terms ban "bots, crawlers, or scrapers" ([Land-book ToS](https://land-book.com/terms-of-service)), even though its robots.txt says AI assistant crawlers are "welcome" ([Land-book robots.txt](https://land-book.com/robots.txt)). The conservative reading is that robots.txt permission to crawl does not override a contractual ban on collecting content. Apify has `scrapers_lat/dribbble-scraper`, `solidcode/behance-scraper` and `solidcode/awwwards-scraper` at $0.003–0.012 per item ([Dribbble Actor](https://apify.com/scrapers_lat/dribbble-scraper); [Awwwards Actor](https://apify.com/solidcode/awwwards-scraper)). They are cheap and should not be used: a paid website-building service is commercial use.

The compliant pattern keeps the human in the gallery and the agent on the open web. The owner browses galleries and pastes two to five links. For an Awwwards or Land-book entry, the agent follows the listing through to the featured live site and analyses only that site, at low volume, respecting robots.txt. Awwwards' footer links an "OpenAPI specification," which hints at an official API ([Awwwards site footer](https://www.awwwards.com/terms-of-use/)). That is unverified and worth one check. When the owner offers no references, the agent's offered options in P2.3 should come from a live web search at intake time, not from a stored corpus.

**A stored reference corpus also collides with Framework B's own repo rule.** The framework's AGENTS.md forbids "business names, domains, addresses, copy or assets from any real site" in the repo. The richest Hugging Face corpus, `ronantakizawa/webui`, offers 36,807 rows covering 12,269 UIs, each at desktop, tablet and mobile with HTML, element boxes and a GPT-4.1 description. It is declared MIT, but it draws from "CodePen, GitHub, Awwwards, WordPress themes, design systems" ([card](https://huggingface.co/datasets/ronantakizawa/webui)). WebUI-350k uses an "other" licence and points to a separate COPYRIGHT.txt ([card](https://huggingface.co/datasets/biglab/webui-350k)). A licence tag on a scraped corpus does not settle copyright in the pages inside it. These corpora could at most back an internal retrieval index that returns links to live sites, and that index would be real-site data outside the framework's brand-agnostic boundary. Building it would also need image embeddings that Workers AI cannot produce. SigLIP2-base (Apache-2.0, 0.38B) would have to run offline ([HF API](https://huggingface.co/api/models?search=siglip2)), or the agent would caption screenshots with a Workers AI vision model and embed the captions with bge or embeddinggemma. The cost is high and the gain over live search is small, so this is not recommended now.

Screenshots of references are best taken by the Playwright that Framework B already runs, at 390, 768 and 1440 px, and stored in private R2 under the site's brief. They never belong in the framework repo or the public build. Apify matters here only for an agent that has no browser. `cheapapi/website-screenshot-api` charges **$0.00089 per screenshot** on Free, offers 13 device profiles, custom widths, full-page capture up to 16,384 px, dark mode and cookie-banner handling, and does not charge for failed captures. It has 273 users and a single rating ([Actor](https://apify.com/cheapapi/website-screenshot-api)). Five sites at three widths costs about $0.013. Apify's own `apify/screenshot-url` is the proven alternative, with 96.3% success over 134,000 runs in 30 days. It charges compute only but takes one viewport width per run ([Actor](https://apify.com/apify/screenshot-url)).

### Competitors and copy: analysis is fine, Google data is not

For reading reference and competitor pages, `apify/website-content-crawler` is the established tool: 170,983 users, 4.62 stars from 235 reviews, compute-only pricing ([Actor](https://apify.com/apify/website-content-crawler)). Most agents can already fetch pages themselves, so it is a fallback rather than a requirement. Section order, offers and calls to action pulled from competitor Markdown feed the brief as analysis. Their copy is never published.

**Local-competitor discovery is Apify's most proven design-adjacent job and also its clearest terms problem.** `compass/crawler-google-places` has 661,611 users and 4.71 stars from 1,818 reviews, and charges $0.004 per place ([Actor](https://apify.com/compass/crawler-google-places)), so eight nearby competitors cost about three cents. It works by scraping Google Maps. The Maps terms (modified 27 January 2026) bar users from copying content and from "mass download or create bulk feeds of the content" ([Google Maps Terms](https://www.google.com/help/terms_maps/)). Pulling five to ten competitor website URLs is the mildest form of that, but it is still Maps data obtained outside Google's APIs. The owner already names two or three competitors in P2.1, so discovery matters only in autopilot. There it should be an owner-approved trial, or should use Google's Places API (pricing not researched).

**Reviews are the sharpest case: real data, trivial cost, wrong terms.** `compass/Google-Maps-Reviews-Scraper` (64,035 users, 4.85 stars from 198 reviews) returns `reviewUrl`, `reviewerUrl`, text, stars, date and owner responses at $0.0006 per review ([Actor](https://apify.com/compass/Google-Maps-Reviews-Scraper)). Fifty reviews cost about three cents, and every one is real and linkable. Republishing them still breaks both rule sets. The Maps terms bar copying. The Places API policies (updated 2026-10-21) require crediting the author, require that end users "always have access to view the individual source photo or review on Google Maps," and forbid pre-fetching, caching or storing content beyond place IDs ([Places API policies](https://developers.google.com/maps/documentation/places/web-service/policies)). A static Astro build caches whatever it renders. The compliant routes are owner-supplied testimonials, given with the reviewer's consent and linked to the public review, or a live Places API fetch with full attribution. That fits Framework B's existing truth gate: every testimonial traces to a source. Yelp and Trustpilot scrapers exist too ([Yelp Actor](https://apify.com/web_wanderer/yelp-reviews-scraper)). Their terms were not checked; assume they are restricted.

## Token extraction: one MIT CLI does what eight young Actors sell

**dembrandt is the best fit found for turning references into DESIGN.md evidence.** Version 0.39.2 was published 2026-10-11 under MIT, billed as "Extract any website's design system in one command. Enforce it in CI." It renders the page with Playwright Chromium and extracts colours with semantic roles and evidence, typography, spacing, borders, shadows, motion, components and breakpoints. It exports `--dtcg`, `--tailwind` (Tailwind v4 `@theme`), `--shadcn` and `--design-md` ("DESIGN.md for AI agents"), with `--color-format oklch`. It can check contrast on real DOM pairs (`--wcag`), crawl several pages, capture dark and mobile modes, run with `--no-sandbox` in Docker, and fail CI on drift (`--compare`, `--tokens file --max-off-token n`). It also ships a GitHub Action and an MCP mode ([npm](https://registry.npmjs.org/dembrandt); [GitHub](https://github.com/dembrandt/dembrandt)). Two flags must stay off. `--stealth` is labelled "authorized use only," and `--key` syncs runs to dembrandt's own service. Neither belongs in a pipeline that respects third-party sites and keeps data in-house. dembrandt was not run in this research, and its GitHub health (stars, issues, commit cadence) could not be read. It is a trial, though a cheap one.

Apify's brand-kit Actors do similar work for a fee, with less evidence. `hydrafetch/website-color-palette-extractor` is the closest match. It returns role-based colours with WCAG verdicts, the type scale, radius, shadow and spacing scales, button styles, a CSS-variables stylesheet, a Tailwind v4 theme and shadcn variables, for **$0.04 per site**. It has 27 users, no ratings and was created 2026-08-22 ([Actor](https://apify.com/hydrafetch/website-color-palette-extractor)). Its README says the optional Apify Proxy needs a paid plan. `eiv/website-brand-extractor-pay-per-event` is cruder (logo, colours, fonts, OG metadata, socials) at $0.002 per brand and does not charge for unreachable sites ([Actor](https://apify.com/eiv/website-brand-extractor-pay-per-event)). The rest of the group (`propped_cloak`, `gazidev`, `urlwright`, `nexgenwatch`, `artifact-machine`) have two to four users each. `urlwright/brand-kit` was created on the day of research ([Actor](https://apify.com/urlwright/brand-kit)). None has a published output schema or an independent rating. With a free in-container tool available, they are fallbacks at best.

Two supporting libraries round out the step. `@projectwallace/css-analyzer` 9.9.4 (MIT, published 2026-10-13) counts colours, font sizes, families, line heights, shadows, radii and units in CSS ([npm](https://registry.npmjs.org/@projectwallace/css-analyzer)). `style-dictionary` 5.7.0 (Apache-2.0) consumes DTCG output if a downstream tool ever needs it ([npm](https://registry.npmjs.org/style-dictionary)). CSS Stats has not been published since April 2022 and is stale ([npm](https://registry.npmjs.org/cssstats)).

Font identification needs licence discipline more than tooling. dembrandt and computed styles already name the font families a reference site uses. Apify's separate font detectors, at about $0.001 per page ([Actor](https://apify.com/maximedupre/font-detector)), add nothing. The image-based case, identifying the typeface in an owner's printed logo, is a real need with weak tools. `dev00/whatthefont-ai-font-finder-monotype-myfonts` charges $0.10 a lookup and says it is "powered by Monotype MyFonts WhatTheFont" ([Actor](https://apify.com/dev00/whatthefont-ai-font-finder-monotype-myfonts)). Whether it uses an official API is unverified, so it should be rejected. On Hugging Face, `dchen0/font_classifier_v4` (Apache-2.0, 0.09B) is the current candidate ([HF API](https://huggingface.co/api/models/dchen0/font_classifier_v4)), and the `gyrojeff/YuzuMarker.FontDetection` Space was running on CPU. Whatever the source, a detected commercial or Adobe face must map to a free near-equivalent. Owner-logo colours need no service: `colorthief` 3.5.0 (MIT, OKLCH output) and `node-vibrant` 4.0.4 (MIT) do it locally ([colorthief](https://registry.npmjs.org/colorthief); [node-vibrant](https://registry.npmjs.org/node-vibrant)).

The governing principle is that extracted tokens are evidence, not a palette to copy. DESIGN.md should record each reference as "inspired by," because lifting a competitor's exact palette, fonts and logo treatment invites trade-dress and brand-confusion claims. That is a judgement, not a sourced legal finding.

## Style generation: structured directions, computed palettes and ranked fonts

**The most transferable idea on Hugging Face is a method, not a model.** "Enabling Creative Exploration for Vibe Design Agents" (September 2026) has a pre-pass propose structured design specifications with typicality scores. An external selector samples one, and the generator then builds that spec "under fixed settings." Across 168 prompts, the authors report this beats raising temperature ([paper](https://huggingface.co/papers/2609.15078)). The method maps directly onto P2.4 (three suggested named styles) and P2.6 (three tiles), and above all onto autopilot. Instead of the agent drifting to its own median, it would emit several direction specs, each with an explicit typicality score, then pick one deliberately, favouring lower typicality within the owner's constraints, and build it with fixed settings. This can go into SPEC.md without adopting any software.

Palettes have no better open source than the ones already chosen. Hugging Face has no palette-generation model; a "palette" model search returns unrelated chat models ([search](https://huggingface.co/api/models?search=palette)). The best dataset is `palettevault/color-palettes`: 10,000 four-colour palettes in HEX, RGB, HSL and OKLCH with WCAG contrast ratios and mood tags, under CC0. Its card is candid: "The palettes are generated, not collected. No designer chose them" ([card](https://huggingface.co/datasets/palettevault/color-palettes)). That makes it safe to vendor into a brand-agnostic repo as an offline candidate pool and fallback for the keyless Huemint API that earlier research found working ([Huemint](https://huemint.com/)). It does carry one generator's taste. The running `google/mood-palette` Space finds "the five most fitting colors from a curated palette" for a mood description, but the model behind it is not named ([Space](https://huggingface.co/spaces/google/mood-palette)). The same idea can be rebuilt on Cloudflare: embed the P2.2 slider adjectives with a Workers AI text embedder and match them against palettevault's tags. Elsewhere, COLOURlovers' API returned a Cloudflare bot challenge (HTTP 403) from the cloud container ([COLOURlovers API](https://www.colourlovers.com/api)), no public Coolors API was found, and Kaggle palette sets are tiny or of unknown licence ([Kaggle API](https://www.kaggle.com/api/v1/datasets/list?search=website%20screenshot)).

**Fonts now have authoritative catalogs; pairing still has no dataset.** A Hub search for "font pairing" returns zero datasets ([search](https://huggingface.co/api/datasets?search=font+pairing)), so the curated pairing pool stays hand-written. Two catalogs can filter and rank that pool. The keyless Fontsource API lists 2,103 fonts: 2,059 under OFL-1.1, 36 under Apache-2.0 and 5 under UFL-1.0, with variable-axis, weight, subset and category fields. Fair use is capped at 2,500 requests per 10 seconds ([Fontsource API](https://fontsource.org/docs/api/introduction); [catalog](https://api.fontsource.org/v1/fonts)). Google Fonts' official Developer API sorts by popularity but needs a free API key ([Developer API](https://developers.google.com/fonts/docs/developer_api)). The undocumented `fonts.google.com/metadata/fonts` endpoint returned popularity ranks for all 1,950 families without a key ([metadata](https://fonts.google.com/metadata/fonts)), but it could change or be blocked at any time. Production should use the documented API.

Fontshare is the catch. Its API lists 100 families: 64 under the ITF Free Font License and 36 under OFL ([Fontshare API](https://api.fontshare.com/v2/fonts?limit=200)). A third-party summary says the ITF licence allows commercial and client use but forbids redistribution, so others must download from fontshare.com ([LicenseOrg](https://www.licenseorg.com/guide/fonts/fontshare)). The primary licence page did not render for this research. Until it is read, any Fontshare face in the curated pool, Satoshi or Switzer for example, should not be committed to a public template, and an OFL equivalent should be the default. Fontshare's view counts also say something about genericness: Satoshi (108,818 views), Clash Display (69,460) and General Sans (59,299) lead, which suggests they are the new reflex "startup" faces.

Personality sliders, this-or-that pairs and the five-word check have no marketplace equivalent and need none. They are owner interactions. The research does reinforce the choice to ask owners to pick between rendered options rather than rate in the abstract, as the next section shows.

## Tiles: render them locally; one new open model deserves an experiment

Rendering the three HTML style tiles to images is already free in Playwright. Apify's HTML-to-image Actor (`moonweil/url-screenshot-api`, $0.004 per item) duplicates that ([Actor](https://apify.com/moonweil/url-screenshot-api)).

**Microsoft's AesCode is the first open model with evidence of beating frontier models at aesthetic HTML, though not on websites.** AesCode-8B and -32B (Apache-2.0, released 2026-10-14) are built on Qwen3-VL-8B, with supervised fine-tuning on 3,000 demonstrations and reinforcement learning over seven reward channels. They output a complete HTML document for slides, posters, dashboards and reports, and can take a reference image as guidance. On the authors' 300-sample infographic benchmark, AesCode-32B scored 85.89 overall and AesCode-8B 82.94, against GPT-5.5 at 81.28 and Claude Opus 4.8 at 80.39. On "Style," "no model clears 60" ([model card](https://huggingface.co/microsoft/AesCode-8B); [paper](https://huggingface.co/papers/2610.18860)). The reward design, deterministic verifiers plus a VLM judge, mirrors Framework B's gates, and the reference-image input mirrors "tile, then build." The benchmark is author-reported and covers infographics, not multi-section marketing pages, and the 8B model needs a GPU. The `hugging-apps/aescode-8b` ZeroGPU Space was running ([Space API](https://huggingface.co/api/spaces/hugging-apps/aescode-8b)), so one offline experiment fits within free quota: give it locked DESIGN.md drafts and compare its tiles with the agent's in a blind pairwise test. It should not become a dependency.

Older screenshot-to-code models are stale for this purpose. They include `HuggingFaceM4/VLM_WebSight_finetuned` (March 2024), `SALT-NLP/Design2Code-18B-v0` (zero recent downloads) and `xcodemind/UICoder` (June 2024) ([HF API](https://huggingface.co/api/models?search=websight)). Their training sets, WebSight (synthetic Tailwind pages, CC-BY-4.0) and Design2Code (484 C4 pages, ODC-BY, images replaced by a placeholder), suit fidelity benchmarks, not taste ([WebSight card](https://huggingface.co/datasets/HuggingFaceM4/WebSight); [Design2Code card](https://huggingface.co/datasets/SALT-NLP/Design2Code)).

## Judging: 36,000 human votes can calibrate the pairwise critic

**The critique gate's weakest assumption is that a vision model's pairwise preference tracks human preference. Hugging Face now holds data to test that assumption.** `datapointai/vibe-landing-page-arena` contains "36,000 pairwise judgments from 3,492 annotators comparing landing pages generated by Claude Code, Cursor, Lovable, and Replit across 100 prompts and 4 design dimensions," spanning 97 business categories and 82 design tones, tagged for Bradley-Terry ranking. It is CC-BY-4.0, gated behind a click-through, and 2.67 GB ([card](https://huggingface.co/datasets/datapointai/vibe-landing-page-arena)). That is close to Framework B's output: AI-built landing pages for small-business categories. A sibling, `datapointai/vibe-design-arena`, compared 60 vibe-coded web apps at 1440×900 across all 1,770 pairs with 30 votes each, about 53,000 judgments. Bolt won 58.6% of comparisons, Cursor 57.3%, Claude 51.3% and Lovable, ChatGPT and Replit 42–45%. Build time correlated with design quality at only r = 0.23 ([card](https://huggingface.co/datasets/datapointai/vibe-design-arena)). That weak correlation is mild support for the three-round critique cap: spending more agent time does not reliably buy better design. The four dimension names were not readable without accepting the gate, so they are unverified. Accepting the click-through, and recording that in DECISIONS.md with the citation, is the first step of the trial.

The trial itself is simple. Sample a few hundred held-out pairs, run Framework B's pairwise judge twice with sides swapped, and measure two things: agreement with the human majority, and whether the judge picks the same page in both orders. If agreement is weak on close pairs, the "accept only if it wins both orders" rule is doing its job and should stay. If it is weak overall, the critique should hand off to the owner sooner. The same pairs can test whether a cheap scorer earns any vote.

**UIClip is the only purpose-built web-UI quality scorer on the Hub, and it is unproven.** The model (`biglab/uiclip_jitteredwebsites-2-224-paraphrased_webpairs_humanpairs`, MIT, 0.15B on CLIP ViT-B/32, October 2024) scores a screenshot against the prompt "ui screenshot. well-designed." Its card gives no numeric metrics, and its example code references undefined variables ([card](https://huggingface.co/biglab/uiclip_jitteredwebsites-2-224-paraphrased_webpairs_humanpairs)). The paper says it "achieved the highest agreement" with 12 designers against baselines ([paper](https://huggingface.co/papers/2404.12500)). It is small enough for CPU inference in CI. Its best possible role is a pre-filter or tie-breaker, and only if it matches the vision judge on the arena pairs. LAION-style aesthetic predictors are trained on photographs and fit UI poorly. Some also carry licence problems: the shunk031 v2 predictor has no licence tag, and the v2.5 Space is AGPL-3.0 ([HF API](https://huggingface.co/api/models?search=aesthetic+predictor); [Space API](https://huggingface.co/api/spaces/discus0434/aesthetic-predictor-v2-5)). The other large preference set, `lmarena-ai/webdev-arena-preference-10k`, forbids redistribution and lets the provider demand deletion and terminate "for any reason" ([card](https://huggingface.co/datasets/lmarena-ai/webdev-arena-preference-10k)). Those strings are wrong for a framework meant to be reused.

**The research also sets a ceiling on any judge, human or model.** DesignPref collected 12,000 pairwise UI comparisons from 20 professional designers and measured Krippendorff's alpha at 0.25 for binary preference. The authors conclude preference is highly personal ([paper](https://huggingface.co/papers/2511.20513)). TASTE found "significant but moderate designer agreement" across nine graphic-design criteria ([paper](https://huggingface.co/papers/2605.20731)). "MLLM as a UI Judge" found GPT-4o, Claude and Llama "approximate human preferences on some dimensions" across 30 interfaces ([paper](https://huggingface.co/papers/2510.08783)). WebGen-R1 names cheap, reliable aesthetic rewards as the bottleneck for training website generators ([paper](https://huggingface.co/papers/2604.20398)). Taken together, these back two existing design choices. Owner picks are authoritative, and no score may override them. The model critique is bounded, and it judges *improvement over the previous version*, not absolute beauty.

Two academic sources offer cheap objective signals next to the vision judge. The Web Design Prototypicality dataset holds about 3,150 homepage screenshots (banking, e-commerce, universities), rated on 7-point scales for prototypicality, aesthetics, usability and trust, all under **CC0 1.0** on Harvard Dataverse ([PMC article](https://pmc.ncbi.nlm.nih.gov/articles/PMC10823051); [Dataverse API](https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/9FKSQI)). It is the only open dataset found that measures *typicality*, exactly the axis the rubric's "could this belong to another business?" question probes. Its three categories do not match small-business sectors, though. Reinecke and Gajos showed that visual complexity and colourfulness, combined with demographics, explain "approximately half of the variance" in appeal judgments made after 500 ms ([paper page](https://www.eecs.harvard.edu/~kgajos/papers/2013/reinecke13predicting.shtml)). Their data link is now dead. Aalto Interface Metrics (MIT) computes such metrics from a URL or screenshot, and its `aim2_metrics` module runs on Python 3.7+ with a CSV-writing CLI ([AIM2 README](https://raw.githubusercontent.com/aalto-ui/aim/master/aim2_metrics/README.md)). Its maintenance status is unknown. Both are trial material: validate on the CC0 ratings before any metric enters the rubric.

## QA: the only new job is benchmarking competitors

Framework B's own build is already covered by free, deterministic tools: axe-core 4.14.0 and Lighthouse 13.5.0 are current on npm ([axe](https://registry.npmjs.org/@axe-core/cli); [Lighthouse](https://registry.npmjs.org/lighthouse)). Apify's equivalents add cost without coverage. These include `constant_quadruped/lighthouse-auditor` (compute only, 264 users), PageSpeed wrappers at $0.004–0.008 a URL and axe wrappers at $0.025–0.05 a page ([Lighthouse Actor](https://apify.com/constant_quadruped/lighthouse-auditor); [PSI Actor](https://apify.com/josh99smith/pagespeed-insights-audit); [axe Actor](https://apify.com/theguide/axe-accessibility-tester)).

**The new QA-adjacent job belongs to the design phase: telling the owner how fast the references and competitors really are.** The CrUX API is free with a Google Cloud API key. It is limited to "150 queries per minute per Google Cloud project," cannot be raised by paying, and updates daily around 04:00 UTC with 28-day aggregates by origin or URL ([CrUX API](https://developer.chrome.com/docs/crux/api)). Attaching LCP, INP and CLS at p75 to each reference card lets the agent mark a beautiful but slow site as a "design-only" reference. Small local competitors often have no CrUX record. For those, the fallback is a lab Lighthouse run in the container, which is free. The Web Almanac supplies the yardstick: the median mobile home page weighs **2.6 MB**, of which images are 911 KB, JavaScript 632 KB and fonts 122 KB ([Web Almanac 2025 Page Weight](https://almanac.httparchive.org/en/2025/page-weight)). A Framework B budget well under that, for example under 1 MB total and under 100 KB of fonts, is a framework choice, not a sourced standard.

Token drift has two candidate checks, which suggests a useful redundancy. Impeccable already flags rendered values outside DESIGN.md, but its detector is a checksum-verified binary whose thresholds cannot be audited (from earlier research). dembrandt's `--tokens DESIGN.tokens.json --max-off-token 0` is an auditable MIT second opinion on the preview URL, and Project Wallace's unique-value counts on the built CSS show whether tokens are actually being used. Both are cheap. dembrandt's gate needs the same trial as its extractor.

UI element detectors add little where the DOM is available. OmniParser v2 can be run under MIT alone, using `icon_detect_v3` with `icon_caption`, but its default `icon_detect` is AGPL-3.0. It needs a GPU, about 0.6 s per frame on an A100 ([card](https://huggingface.co/microsoft/OmniParser-v2.0)). Its one niche, catching text baked into images or rendered overlaps the DOM misreports, does not justify the dependency now. For the reference sites' technology stack (which booking or CMS tool competitors use, which hints at integrations the brief needs), `simple-wappalyzer` 1.1.108 (MIT, published 2026-10-17) detects technologies from HTML and headers without a browser ([npm](https://registry.npmjs.org/simple-wappalyzer)). The original `wappalyzer` package is deprecated ([npm](https://registry.npmjs.org/wappalyzer)).

## Images: neither marketplace beats Workers AI and owner photos

Neither Apify nor Hugging Face changes the image plan. Owner photos come first, Openverse's keyless CC-licensed results with licence and creator fields come second ([Openverse API](https://api.openverse.org/v1/)), and generated images are reserved for texture and abstraction. Workers AI's 10,000 free daily Neurons cover FLUX-class texture generation ([Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/index.md)). The open alternatives on Hugging Face, Z-Image-Turbo and Qwen-Image (both Apache-2.0), run only through paid providers such as fal-ai and Replicate. Free accounts get no provider credits ([Z-Image API](https://huggingface.co/api/models/Tongyi-MAI/Z-Image-Turbo); [Inference Providers pricing](https://huggingface.co/docs/inference-providers/pricing)). They belong in "optional paid," for use only if Workers AI quality falls short. Per-image prices were not captured.

One overlooked use does fit. Photo aesthetic predictors are poor UI judges, but they were built for photos, and owners often hand over dozens of phone pictures. `trojblue/distill-q-align-aesthetic-siglip2-base` (Apache-2.0, 0.09B) could rank those for hero and section slots in CI ([HF API](https://huggingface.co/api/models/trojblue/distill-q-align-aesthetic-siglip2-base)). The owner would still confirm the picks. This is a low-priority trial. Two firm exclusions apply. Screenshot datasets never feed site imagery. Photos attached to scraped Google reviews (`reviewImageUrls`) carry the same terms problem as the review text.

## "What is generic" now has numbers

**The Web Almanac's 2025 fonts chapter, built from a July 2025 crawl of 16.2 million sites, gives the first defensible genericness baseline.** Roboto appears on about 10–10.7% of pages, Poppins on 5.8–6.0%, Open Sans on 5.0–5.6%, Montserrat on 3.3–3.9% and Inter on 1.4–1.5%, which the chapter calls "one notable climber." Google Fonts is on about 54% of desktop and 47% of mobile sites, `system-ui` is on about 9.7% of pages, and variable fonts are on about 40% ([Web Almanac 2025 Fonts](https://almanac.httparchive.org/en/2025/fonts); [methodology](https://almanac.httparchive.org/en/2025/methodology)). Google Fonts' own popularity rank agrees at the top. The first twenty are Google Sans, Roboto, Montserrat, Open Sans, Inter, Lato, Poppins, Arimo, Noto Sans JP, Roboto Condensed, Roboto Mono, Noto Sans, Raleway, Nunito, Nunito Sans, DM Sans, Oswald, Outfit, Plus Jakarta Sans and Work Sans ([metadata](https://fonts.google.com/metadata/fonts)). That list, refreshed from the documented API, is a better source for the "needs a reason" font flag than any blog's opinion. It is also a ranking, not a ban: a top-40 face as a headline choice needs a stated reason, while a face ranked below about 300 is a distinctiveness candidate.

Colour data is older. There has been no CSS chapter since 2022, and `/en/2025/css` returns 404. The 2022 chapter found #RRGGBB in 49% of colour occurrences, custom properties on 43% of pages, and `linear-gradient` on **76% of pages**. It did not rank actual colour values ([Web Almanac 2022 CSS](https://almanac.httparchive.org/en/2022/css)). The most practical known-generic palette list is the defaults Framework B already knows models fall back to: Tailwind's default palette and shadcn's defaults. They can be read directly from those packages.

**HTTP Archive's Reports API is the cheap live source.** It is free, needs no key, and returned September 2026 adoption counts in a live test. Bootstrap was on about 26% of origins, Font Awesome about 21%, WordPress about 30%, Tailwind about 8%, Elementor about 9–10% and Astro about 0.6% (percentages computed from the API's counts; [tech-report-apis README](https://raw.githubusercontent.com/HTTPArchive/tech-report-apis/main/apps/report-api/README.md); [Tech Report](https://httparchive.org/reports/techreport)). Its terms and rate limits are undocumented. Its Google-Fonts figure of about 43% disagrees with the Almanac's 54/47% because it counts Wappalyzer-detected origins rather than font requests, so the docs should cite one source consistently. Tailwind on 8% of origins means using Tailwind is not itself a tell. Tailwind's *defaults* are.

BigQuery is the deep but dangerous option. On-demand queries are free for the first 1 TiB a month and cost $6.25 per TiB after that ([BigQuery pricing](https://cloud.google.com/bigquery/pricing)). The sandbox needs no card but expires tables after 60 days ([sandbox docs](https://docs.cloud.google.com/bigquery/docs/sandbox)). HTTP Archive's `crawl.pages` is about 30 TB and `crawl.requests` about 199 TB. A rank-filtered top-1,000 query read 329 MB, while one unfiltered custom-metric field read 6.56 TB ([minimizing costs](https://httparchive.org/docs/guides/minimizing-costs)). One user reported a **$14,000 charge in two hours** ([HTTP Archive Discuss](https://discuss.httparchive.org/t/warning-14-000-bigquery-charge-in-2-hours/2715)). An agent may only run such queries with `maximum_bytes_billed` set, a date, client and rank filter, and owner approval of the service account. Even then, the custom-metric names for CSS colours are unverified.

The most specific genericness signal is local. Running dembrandt on 10–20 same-category competitors near the owner, and counting recurring hues, families and radii, yields a *category-generic* token set. The draft DESIGN.md can be scored by its distance from that set. This is untested, but it is the only measure here that knows what "generic" means for a given town and trade. Common Crawl (latest CC-MAIN-2026-43) has no industry labels and needs AWS Athena ([Common Crawl](https://commoncrawl.org/latest-crawl)). BuiltWith's free API returns only counts per technology group ([BuiltWith Free API](https://api.builtwith.com/free-api)), and Wappalyzer's API needs plans from $250 ([Wappalyzer pricing](https://www.wappalyzer.com/pricing/)). None is worth it for the design phase.

## What remains unverified

Several load-bearing facts were not confirmed and should be settled before SPEC.md cites them. dembrandt was never run, and its repository health is unknown. No brand-kit Actor's output quality was tested, and hydrafetch publishes no output schema. The arena datasets' dimension names sit behind the click-through. UIClip has no published accuracy, and AesCode has not been tested on landing pages. Transformers.js in Workers is untested. Fontshare's primary licence text did not render. The Google Fonts metadata endpoint and the HTTP Archive Reports API have no documented terms or rate limits. The CrUX API was not live-tested, and whether a BigQuery service account can use the no-card sandbox is unknown. On the platform side, Apify's Free-plan retention for unnamed storage is unclear (an Academy page says 7 days), and the compute-unit costs of the official Apify Actors were not measured. Whether Awwwards has an official API, how many reviews the Places API returns per place, and what Yelp's and Trustpilot's terms say all remain open. So do whether calling someone else's ZeroGPU Space spends the caller's quota, the HF PRO subscription price, and Vectorize pricing, which was not researched.

None of these blocks the adopt list. Each trial above is designed to settle one of them.

## Conclusion

The two platforms the question named turn out to matter less than the free public infrastructure around them. The real gain is evidence: measured genericness from the Almanac and font popularity, real-user speed from CrUX, a first human-labelled yardstick for the critic, and an extractor that turns any URL into the same DESIGN.md format the phase locks. Apify and Hugging Face mostly sell or host versions of things Framework B can run itself for free. Their distinctive offerings are weakest exactly where agents are most tempted to use them, in galleries and reviews, because those are the terms-protected places.

The practical consequence is an ordering of work, not a shopping list. The calibration trial with the landing-page arena should run first. It decides how much the bounded critique can be trusted, and therefore how much of autopilot can rest on it. The dembrandt trial should run second, because a passing result gives the reference, generic-data and drift-gate steps a single free engine. Everything else is optional, and keeping the marketplace pieces optional is also what keeps Framework B agent-agnostic and brand-agnostic.
